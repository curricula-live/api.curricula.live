# Recorded graph queries

The API returns indexed TDB2 adjacencies in ascending graph layer, predicate, subject and object order, using the full graph IRI to break ties. Relationship offsets and limits apply after filtering and ordering. A relationship page belongs to the publication active when requested. Check the active manifest digest if requesting several pages across a possible release switch.

Neighborhoods use breadth-first expansion of the filtered adjacencies. The root is always included. A domain filter applies to adjacent concepts through their recorded SKOS scheme membership. The response reports when its edge or node budget excludes a recorded statement, and includes metadata for registered canonical nodes. An edge that occurs in two named graphs appears twice, with its respective graph IRIs. Within a single graph, following both ends of an edge still produces one edge, preserving the recorded subject and object.

Pass an exact predicate IRI and adjacent endpoint to the provenance endpoint to inspect direct evidence for an edge. For edges whose object is the focus, request incoming evidence. Evidence comes from producer statements in the provenance graph. The API returns witness identifiers and source references as recorded, including absent values.

The ontology registry associates each producer ID with a disjoint namespace and derives its named graph IRIs from that namespace. Formal-sciences short URLs continue to resolve against the formal-sciences namespace. Exact IRI endpoints support registered producers with identical local names, and graph exploration can follow recorded links across their graphs, preserving the source graph IRI. The integration test constructs two producers in a shared dataset to exercise these properties. Persistent ingestion currently activates one formal-sciences release. Supporting additional producer packages will require extending verification and activation to combine independently pinned releases.
